# 2026.241.1204 — ci: pin the gate at a charly that supports schema 2026.240.1943

## Summary

The candy workflow in this repo was scaffolded from an existing layer repo and inherited its charly pin, `v2026.238.1242`. That charly predates the org-wide schema migration and caps at schema `2026.232.0520`, so it rejects this manifest before validating anything about it:

```
charly: error: command "validate": validation error: charly.yml:
  config schema 2026.240.1943 is newer than this charly supports (max 2026.232.0520).
```

This advances the pin to `v2026.241.1130`, whose own `charly.yml` carries the same `2026.240.1943` stamp. **The manifest is unchanged** — only the version of charly the gate runs.

## How tested

The manifest validates clean against a charly built from current `main` (schema `2026.240.1943`, the same schema `v2026.241.1130` carries):

```
$ charly box validate
box validate exit=0
```

and the candy passes its full `disposable: true` bed on a fresh rebuild:

```
charly check run check-hypr-layer: PASS (steps=13)
total errors: 0 | warnings: 0
```

The CI failure was a gate-version problem, not a manifest problem: the same manifest that CI could not read validates and builds correctly under a charly that supports its schema.
