# 2026.243.0603 — chore: advance the pinned plugin-wl to the tag carrying hypr-layers

## Summary
    require:  @github.com/opencharly/plugin-wl/candy/plugin-wl
              v2026.242.0610 -> v2026.242.2204

### Why

v2026.242.2204 is the first tag carrying `wl: hypr-layers` (plugin-wl#7). This candy is the
nested-compositor primitive, and layer-shell surfaces — a bar, a notifier, a launcher, an OSD,
a lockscreen — are exactly what a Hyprland desktop puts on screen and what `hypr-clients`
cannot see, because none of them is a toplevel. Pinning the tag that predates the method left
every consumer of this candy unable to assert anything about them.

It is also the last pin in the chain holding plugin-wl at two versions across the org:

    distro-omarchy/box/omarchy-cstream  -> layer-cstream-desktop:v2026.242.0422
                                        -> pod-hyprland:v2026.241.1545
                                        -> plugin-wl:v2026.240.1326

A bed in distro-omarchy that pins plugin-wl at v2026.242.2204 for its own `wl:` steps
therefore resolves the candy at two versions and charly warns:

    Warning: candy github.com/opencharly/plugin-wl/candy/plugin-wl resolved to multiple
    versions; using newest 2026.242.2239 (from …@v2026.242.2204), ignoring 2026.187.1200
    (from …@v2026.240.1326)

Measured A/B on that bed: with the pin, 4 such warnings; with the pin removed, 0. The second
version is introduced by the consumer's pin meeting THIS candy's older one, so the fix belongs
here — advancing the tail of the chain — not in a per-consumer override.

This is the first of three ordered repins: this candy, then layer-cstream-desktop, then the
distro-omarchy box that pins it.

## Compatibility

plugin-wl#7 ADDED a method (`hypr-layers`) and moved the wl skill entities into the plugin that
serves them. It removed nothing this candy uses, so the bump is additive: the `wl:` methods
this candy's own checks already call are unchanged.

## How tested

    $ charly box validate
    [exit 0]

This repo declares one candy and no bed (`disposable: true` appears nowhere in it), so
`charly box validate` IS its gate — there is no bed to run here. The bump is proved END TO END
by the consumer that needs it: opencharly/distro-omarchy's check-omarchy-desktop-vm, whose
`wl: hypr-layers` assertions ran green against a live Hyprland and caught the bar being parked
off-screen at y=-26 while staying mapped.
